実物の格闘ゲームスプライトと2D中割りの追加研究

2026-10-16（日本時間）。P18/P19の失敗と、ユーザーの「実際のパターンを研究したか」という指摘を受けて実施。制作前には実作品のコマ単位解析をしていなかった。従来のP15調査は再生・データ構造が中心で、この研究の代わりにはならない。 新しい画像生成は行っていない。制作Skillは作らない。

今回、実際に確認したもの

  1. Fighters Generationに掲載されたリュウの前進・後退・SFA名の歩行・弱パンチ・強キック、サスカッチの歩行・指弾き、計7GIFをダウンロードし、全コマを分解。前歩き、サスカッチ歩行、弱パンチの全コマ一覧を目視。ファイルごとの合成フレーム数、保持時間、画素hashを記録した。
  2. Ikemen-GO-Screenpack同梱Kung Fu ManのAIR/CNS/DEF/readmeをcommit ab606f77ab85a344fb603a7bffd79935abdd8e89 で取得。待機、前進、後退、弱パンチ、強パンチ、弱キックの再生要素と保持tickを解析した。これは公開サンプルの実装値で、SFやSkullgirlsの内部データではない。
  3. Mariel Cartwright（Lab Zero Gamesリードアニメーター）のGDC 2014講演 Fluid and Powerful Animation within Frame Restrictions の公開スライド全37ページのテキストを確認。p.9とp.20は描画したページも確認。講演動画全編は未視聴。
  4. Richmond Leeの Darkstalkers and the Twelve Principles of Animation を全文確認。実作スプライトを使った二次分析であり、Capcom自身の制作記録とは区別する。

各原資料の取得hash・分解値・参照URLは末尾のJSONに記録しています。

目視で確認した動き

  • リュウ前進はガードを保つ運足。11コマの中で足の前後関係・足裏の見え方が変わり、上体の向き・帯・鉢巻が連動する。通常歩行の大きい腕振りをそのまま当てはめる参考ではない。
  • サスカッチは頭胴が大きく脚の短い体型。胴で脚の付け根が隠れても、足の輪郭、持ち上がった足と地面にある足、体の上下・傾きの変化で踏み替えが読める。今回のモンスターは人型の脚の運動だけでなく、この体型の見え方を研究対象にする。
  • リュウ弱パンチの掲載5コマでは、伸ばした腕を平均位置で細かく埋めるというより、動作が読める姿勢・伸展・戻りが強く選ばれている。これはGIFの目視所見であり、Capcomの原画割り当て資料を読んだという意味ではない。
  • どちらの歩行も、横方向のゲーム画面だから身体を厳密な真横の一方向へ固定して描く、というものではない。胴体の立体的な向きや重なりを残している。カメラ仰角とキャラクターの作画上の向きを混同しない。

実装値で分かった「絵の枚数」と「ゲームのフレーム」の違い

KFMのAIRは group,image,x,y,time の再生要素を並べる。以下は同梱ファイルの実測。

弱パンチ200の絵の参照順は 200,0 → 200,1 → 200,2 → 200,1 → 200,0。保持は 2 → 1 → 4 → 3 → 2 tick。同じ中間の絵200,1を、出す時1tick・戻す時3tickで使う。絵3種類、再生要素5、通常進行12tickを混同しない。

3番目の要素にClsn1（攻撃判定）があり、CNSは AnimElem = 3 でHitDefを設定する。pausetime = 8,8 も指定される。絵の長さだけで命中時の見た目の長さを決めてはいけない。強パンチには命中時に戻りの要素へ送るChangeAnimもある。

一方、前進20は16枚すべて3tickずつ。均等保持が必ず悪いのではない。 同じ時間刻みでも絵の位置の間隔（spacing）で速度変化を作れる。必要なのは「全部均等」か「全部不均等」かの決め打ちではなく、動作を読める配置と時間で設計すること。

CNSの walk.fwd=2.4、walk.back=-2.2 は画像とは別の移動設定。歩幅と実移動の整合は、スプライトを並べるだけでは検証できない。今回ゲームを起動して足滑りや当たり判定を実測したわけではない。

制作者の説明から確認した原画・中割りの扱い

GDCスライドのページ番号はPDFの1始まり。

  • p.6–9：キーのシルエットが基礎。予備動作と、中割りでキーを強調すること。
  • p.10–16：followthrough、smear、overshoot、意図的な身体の誇張を使って動きを伝える。これは生成の不整合を何でも許すことではない。
  • p.17：一枚ごとの絵の完成ではなく、動きを作っているという注意。
  • p.19：Rough → Implement → Finish → Implement。ラフをゲームへ入れた検証が仕上げより先。
  • p.20：弱・中・強攻撃の目的とゲーム設計側の要件から、ラフ段階のコマ数ガイドを決める。
  • p.21–22：各絵を同じ時間で保持することに縛られず、キーや周辺の絵の保持を使い分ける。
  • p.23–25：hitstop、動いている待機への出入り、ゲームの応答性も作画と併せて扱う。
  • p.27：攻撃を anticipation / smear / main key / return で考える。
  • p.30–31：Filiaの21枚の例から6枚減らし、キーの重点を上げて力強くした比較。
  • p.32–33：Cerebellaの45枚の例を29枚へ減らして姿勢を明瞭にした比較。講演時の比較例であり、現行製品の全技の規格ではない。

Art Eaterの記事は、pose-to-poseとstraight-aheadの使い分け、衣装の遅れ、弧、均等でない位置と時間、肩と腰から動作を導くこと、体積感のある作画を説明する。Capcomの実際の制作手順だと断定している箇所は記事側の推測も含むため、こちらの実証事実とはしない。

前の制作方針で修正すること

  1. 24枚／48枚を最初の達成目標にしない。 シルエット・足の同一性・体積・支持／遊脚・動作の目的が読めるラフを先に通す。
  2. 原画間を一律の角度差・一律の時間で埋めるだけを中割りと扱わない。足・腰・肩・手の軌道、詰めと抜き、保持時間、遅れを設計する。
  3. エリア移動の通常歩行と、ガードを維持する戦闘の前進・後退を分ける。格闘ゲームからは目的に合う部分を参照し、腕振りを機械的にコピーしない。
  4. 彩色や質感を完成させる前に、全身1枚のラフ連番をプレイヤーへ入れて、通常速度・一歩ごと・ループ・移動との同期を確認する。色付きの良い絵1枚を動作成立の証拠にしない。
  5. 中割りには「前後の原画」「脚・手の識別」「接地」「軌道」「保持」「重なりが切り替わる場所」を指定し、受け入れ時は並べて確認する。P19の指示文に書いただけでは達成にならなかった。
  6. 道具の追加は工程の一部。GPUや時系列生成ツールがあれば自動で原画・中割りが成立するとは言わない。前回は作画と時間設計の不足を、道具の不足へ寄せすぎた。
  7. 1方向の歩行が成立するまで、8/16方向・別仰角・攻撃の量産と制作Skill化は進めない。

未実施

GDC講演動画の通し視聴、元ゲームを動かした60Hz録画・入力・コマ送り・当たり判定との照合、元ゲーム版の確定と原画台帳照合、手足や腰の座標を全コマで追った定量的な軌道解析、DQ各作品の戦闘動画のコマ解析、新しいモンスターのラフ動作の成立確認。したがって「格闘ゲームを十分に研究し終えた」「この方法なら必ず生成できる」とは扱わない。
